# ADR 0035: 中观层（300 米–3 公里路网流量）——评估与决定

- 状态：**已评估，决定暂缓不建**（2026-10-06）。本文是评估记录与触发条件，
  不是实现方案。
- 相关：ADR-0034（选址 → 场景流水线，D2 的「集客区 / 场地」二分）、
  `docs/选址沙盘-定位与执行计划.md` 第 8 步、`docs/CLAIMS_LEDGER.md`。
- 本文用中文写，因为这条线的决策人是中文读者；其余 ADR 为英文，属既有惯例。

## 背景

用户要求「必须 3 公里左右」。3 公里半径 = π·3000² ≈ 28.3 km²。
按路网密度 ~10 km/km²（**自拟**）、人行道有效宽 ~3 m（**自拟**）估算，
可步行面积约 849,000 m²。当前 `crowdBudget.maxAgents = 2,000`，
即人均 425 m² —— 一条空街。要让人均 4 m²（真拥挤）需要约 21 万人。

**结论：卡住 3 公里的不是算力，是稀疏。** 100k agents 的 GPU 实测是
0.45–0.46 ms/step（`packages/core-gpu/BENCHMARKS.md`），人数从来不是瓶颈；
把 2000 个人撒在 28 km² 上才是。

## L1 中观层是什么

不做微观行人仿真，而是把 300 m–3 km 建成一张中观网络：

- 节点：小区 / 写字楼 / 学校 / 公交站 / 地铁站 / 竞品门店
- 边：路网路段
- 模型：重力模型或介入机会模型，把需求分配到节点之间，得到

  1. **各方向来人比例** —— 人主要从东边来还是从地铁口来
  2. **竞品分流后的需求份额** —— 竞品在 300 m 外新开一家，我掉多少

## 它能回答的两个问题，以及为什么现在不必答

### 问题一：门开在哪一侧

这是 L1 最有价值的产出，也是唯一影响**场内布局**结论的产出。

但第 4 步（`arrivalCalibration.ts`）已经用更好的办法回答了它：商场闸机 /
红外计数器的**每个门分时进店人次**，是实测数据。一个真数据点胜过一整个
未标定的分配模型。街边店没有闸机，但可以用人工蹲点数小时拿到同样的东西。

→ 门的位置问题用**实测**解决，不用模型。

### 问题二：竞品分流

`demandInference.ts` 的 `competitorRetention`（每个竞品保留 94%，**自拟
未标定**）已经在做这件事。它绝对不可信，但它是**同一个系数下的相对比较**，
而这正是本产品唯一在卖的东西（见 `layoutComparison.ts` 的头部注释）。
换成一个同样未标定的重力模型，不会让任何一个结论变得更可信，只是让它
看起来更专业。

## 决定：暂缓

**不建 L1。** 理由按重要性排序：

1. **它不改变产品能卖的那句话。** 产品卖「A 布局比 B 布局排队短 40%」，
   这个结论全部产自场地内部（≤300 m）。L1 不进入这个比较。
2. **它没有可标定的输入。** 中观分配模型需要分向 OD 流数据才能标定，
   而我们连一个门的分时计数都还没拿到。现在建，产出的每个数字都要进
   `CLAIMS_LEDGER.md` 登记为未标定，和现在的 `competitorRetention` 同级。
3. **它有一个更便宜的替代品。** 分向来人比例 = 每个门的实测计数（第 4 步）。
   模型能提供的最好结果也就是逼近这个数。

## 触发条件（满足任一则重新启动评估）

- 拿到**至少两个门的分时真实客流**（同一商场或同一条街），此时 L1 有了
  可标定的目标量，可以从「未标定的分配模型」升级为「拟合到实测的分配模型」。
- 有客户明确要求回答「竞品开在 X 处我会掉多少」的**绝对**数字，且接受
  该数字带误差区间。今天给不出这个，也不该给。
- 场内布局的结论开始被「人从哪边来」主导（例如门的候选位置超过两个且
  实测无法覆盖），那时 L1 才进入核心比较链。

## 如果将来要建，最小形态（避免以后重新讨论）

1. `src/site/catchmentNetwork.ts`：节点 = POI 聚合点，边 = 路段，
   权重 = 步行距离（用 `geo/projection.ts` 的米制投影算，不要用经纬度）。
2. `src/site/assignDemand.ts`：重力模型，距离衰减指数作为唯一待标定参数，
   **一个参数**，标定到实测分门计数。
3. 输出不是「人流仿真」，而是**每个场地入口的到达率份额**——
   落到 `entranceSchema.arrivalProfile`，与第 4 步的实测路径同一个落点。
   两条路能互相校验：模型分向 vs 实测分向。
4. 不模拟 2 公里步行。ADR-0034 D2 已经写明：那段路是场地边界上的一个
   到达率，不是一群走路的人。这一点不因 L1 而改变。

## 后果

- 3 公里仍然「被建模」，但建模方式是**集客区统计 → 场地边界到达率**，
  不是路网流量。这一点必须在 UI 上说清楚，不能让人以为 3 公里内有人在走。
- `catchmentToArrivalProfile` 的系数保持未标定状态，并在
  `CLAIMS_LEDGER.md` 持续登记（已完成，见 2026-10-06 条目）。
- 第 8 步的产出就是本文，不产生代码。
