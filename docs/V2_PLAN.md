## 1. v2 三大主线（按优先级）

### 主线 A：可信度（没有它产品卖不出去）

仿真工具的生命线是结果可信。AnyLogic 卖得贵，是因为客户拿它的报告去过消防审批和董事会。

- 与行人动力学公认基准对标：基本图（密度-速度关系）、瓶颈通行能力、RiMEA 测试场景集
- 仿真报告导出：PDF 报告（场景快照、参数表、疏散曲线、密度峰值、与规范阈值对比）
- 确定性复现验证：同种子同结果，跨浏览器误差在容差内

### 主线 B：产品化（从单机玩具到多人可用）

- 轻后端：账号、云端场景库、只读分享链接（发给领导/客户直接在浏览器看仿真回放)
- 行业模板库：地铁站厅、商场、体育场散场、机场安检，开箱即改
- 结果回放文件：仿真录制为轨迹文件，可脱离实时计算播放

### 主线 C：AI 差异化（v1 刻意推迟的部分）

- 自然语言建场景："周五晚高峰地铁站，B口封闭，3000人/小时进站" → 生成 .csim.json
- AI 报告解读：仿真跑完自动生成结论与改进建议（"建议在西侧增加一个2米出口，疏散时间可缩短约40%"——由 AI 提出假设、引擎批量验证）
- 批量实验（Experiment Runner）：参数扫描 + 多方案对比，这是 AI 建议闭环的基础设施

## 2. 里程碑与任务

### M5 可信度与校准（~5 任务）

- [ ] T5.1 基准测试集：实现 RiMEA 核心场景（直廊、瓶颈、转角、对流）为自动化测试，输出与文献值对比表
- [ ] T5.2 基本图校验：密度-速度曲线自动绘制，与 Weidmann 曲线对比，调参至合理区间
- [ ] T5.3 参数预设系统：人群类型预设（通勤/购物/老幼混合），参数带文献出处注释
- [ ] T5.4 PDF 报告导出：场景图、参数、关键指标、疏散曲线、合规阈值对照（纯前端生成）
- [ ] T5.5 复现性测试：固定种子跨 Chrome/Edge/Safari 结果一致性 CI（容差断言）

### M6 实验系统（~4 任务）

- [ ] T6.1 仿真录制/回放：轨迹压缩存储（增量+量化），回放器独立于仿真引擎
- [ ] T6.2 Experiment Runner：参数扫描（如出口宽度 1~4m 步长 0.5），后台 Worker 串行批跑，无渲染加速模式
- [ ] T6.3 多方案对比视图：并排回放 + 指标对比表
- [ ] T6.4 蒙特卡洛模式:同配置多种子批跑，输出指标分布（均值/P95）而非单次结果

### M7 轻后端与协作（~5 任务）

- [ ] T7.1 后端选型与搭建：建议 Supabase 或 Cloudflare Workers + D1/R2（场景文件和回放文件是对象存储友好的）
- [ ] T7.2 账号与项目空间：登录、场景云存储、版本历史
- [ ] T7.3 只读分享链接：免登录打开回放+报告页
- [ ] T7.4 模板库：6 个行业模板场景，含推荐参数与说明
- [ ] T7.5 用量与配额基础设施（为收费做准备，先只埋点不收费）

### M8 AI 层（~4 任务）

- [ ] T8.1 自然语言→场景：Claude API 结构化输出 .csim.json（schema 约束 + 校验回路：生成→zod校验→失败回喂错误重试）
- [ ] T8.2 自然语言→事件脚本：把"18:05 西门突发关闭"翻译为 DES 事件
- [ ] T8.3 AI 分析报告：输入仿真统计 JSON，输出结论建议；建议自动转化为 Experiment Runner 的对照实验去验证（AI 提假设，引擎做证明）
- [ ] T8.4 API Key 安全：AI 请求走自己的后端代理，密钥不落前端
- [ ] T8.5 **AI 描图管线（图像→场景几何）**：用户上传卫星图/CAD平面图/楼层图 → 多模态模型（视觉 API）识别墙体轮廓、出入口、通道、商铺分区 → 输出 .csim.json 初稿 → 编辑器内以"AI 图层"叠加在原图上供人工校正确认。验收：3 张真实商场平面图，AI 初稿描图工作量比纯手工减少 ≥60%
- [ ] T8.6 描图管线工程化：比例尺标定（用户标两点定真实距离）、几何清洗（线段合并/吸附/闭合检测）、置信度低的区域高亮提示人工复核

### M9 规模与体验（按需）

- [ ] T9.1 多楼层与楼梯/扶梯（v1 边界解除）
- [ ] T9.2 50万 agent 冲刺（多 Flow Field 纹理图集、间接绘制）
- [ ] T9.3 3D 视图打磨与一键演示模式
- [ ] T9.4 **真实城市 3D 底图**：集成 Google Photorealistic 3D Tiles（3d-tiles-renderer 加载进 Three.js WebGPURenderer），仿真场景可锚定到真实地理坐标，户外疏散场景带真实城市环境展示。注意：Tiles 仅作视觉底图，碰撞几何仍以 .csim.json 为准
- [ ] T9.5 （可选）开源 3D 生成资产接入：评估混元 HY-World 2.0 等开源模型生成的 3D 场景资产作为展示层素材的导入格式（glTF），不参与仿真计算

### M10 神经修正层（研究性，物理模型为主干）

> 原则：物理社会力模型是可解释、可审计的主干，神经网络只做两件事——标定参数、修正残差。报告中必须可一键关闭神经修正项并对比结果。

- [ ] T10.1 数据准备：接入公开行人轨迹数据集（如走廊/瓶颈实验数据），转换为统一训练格式
- [ ] T10.2 参数自动标定：用轨迹数据优化社会力参数（A、B、τ 等），按人群类型输出预设包，替代手调
- [ ] T10.3 神经残差修正项：训练小型 MLP 预测社会力残差（输入：局部密度/相对速度等特征），蒸馏后以 WGSL 实现，在 GPU compute pass 内联推理；M5 基准回归必须全部通过才允许默认开启
- [ ] T10.4 对比验证报告：同场景"纯物理 vs 物理+神经修正"与真实数据的误差对比，作为营销与可信度素材

## 3. v2 边界（仍然不做）

- ❌ 不做实时多人协同编辑（分享是只读的）
- ❌ 不做移动端编辑（回放分享页可适配移动端查看)
- ❌ 不做车辆/轨道仿真
- ❌ 不接视频流式世界模型（Genie/Happy Oyster 类）——输出是视频不是几何，无法用于仿真；只接"真 3D 资产/瓦片"做展示层
- ❌ 不自训大模型；M10 仅训练小型标定/残差网络（万级参数），且默认可关闭
- ❌ 不做私有化部署（有客户真金白银要求时再说）

## 4. 与开发并行的非代码工作（这些 Claude Code 替你做不了）

1. **找 3~5 个种子用户**（商场运营、安保公司、消防咨询），M5 一完成就拿报告功能去聊。v2 排期应随他们的反馈调整——这比本文档任何一条都优先。
2. **定价假设**：免费（单机+水印报告）/ Pro（云存储+无水印报告+批量实验）/ 企业（按项目）。M7 的配额埋点为此服务。
3. **合规口径**：报告措辞注明"仿真结果供决策参考"，避免承担消防审批责任；找一位消防/建筑顾问把关报告模板。
4. **内容营销素材**：M6 的对比回放天生适合做演示视频（"出口加宽前后对比"），每个里程碑产出一个可发布的 demo。

## 5. 执行建议（给 Claude Code 的工作方式）

- 每个里程碑结束更新 CLAUDE.md 的"当前进度"与命令清单
- T8.x 涉及密钥与外部 API，相关代码评审从严，禁止密钥出现在前端包或仓库
