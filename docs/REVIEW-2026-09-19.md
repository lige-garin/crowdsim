## 1. 项目现在在哪

### 规模

- 6 个包（`app` / `backend` / `collab` / `core-behavior`(Rust) / `core-gpu` / `scene-schema`）
- 约 **60,000 行** TS/TSX（含测试），`packages/app/src` 365 个源文件
- **168 个测试文件**，9 条 e2e，9 个 ADR，1 本诚信台账 `docs/CLAIMS_LEDGER.md`
- 最大文件 634 行（2026-07-28 时是 1703 行）→ 文件瘦身这轮**已经做完了**

### 能力地图

**A. 已经真做出来、且有证据的**

| 能力                                         | 证据                                                                                                                                                 |
| -------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |

| 渲染                                         | WebGPU 3D：GTAO、泛光、FXAA、昼夜太阳、雨、接触阴影、玻璃门面发光店招、远近分级                                                                      |
| 诚信治理                                     | `docs/CLAIMS_LEDGER.md` 把「10万 GPU」「70% 工作量削减」「跨浏览器复现」「MLP 蒸馏」等伪造宣称逐条改判并处置                                         |

**B. 写完了但没接进产品（半成品）**

- **100k GPU 步进核**：`packages/core-gpu` 真机实测 0.446–0.465 ms/step，但 `packages/app/src` 里 `gpuSimCore` **零 import**（grep 已核实），只有 `test-webgpu/` 引用。等于是做了个没装到车上的发动机。
- `packages/app` 默认仍是 CPU 路径，`maxAgents` 上限 2000。

**C. 结构性空白**

- **多楼层 / 垂直交通**：`world: {width, height}` 是单层二维，这是硬阻塞（`verticalTransport.ts` 已于 2026-08-30 作为孤儿删除）。
- **真实轨迹标定**：现在是对**已发表曲线**拟合，且参数不唯一（存在另一组拟合误差更低但 SFPE 更差的参数）——曲线本身无法识别模型。
- **生产鉴权**：`POST /api/auth/login` 已 fail-closed，但生产必须注入真实 verifier，否则所有人登录不了。

## 2. 基础扎实吗？——分层判断

### 结论：地基扎实，甚至在这个体量里属于少见地扎实；但它是「技术内核扎实 + 交付外壳未完成」，不是「产品就绪」。

**扎实的证据（这些不是自我声明，是可复核的）**

1. **文献有出处、拟合有留出验证**。社会力参数不是拍脑袋，是对 Weidmann 曲线拟合 + 留出密度/种子 + SFPE 独立公式双对照，并且**自己写明了「参数不唯一」**。这种自我设限在同类项目里很少见。
2. **有一本诚信台账，而且是真的在用**。它把「10 万 agent」「跨浏览器复现矩阵」「70% 工作量削减」「4-3-2 MLP 蒸馏」这些曾经的漂亮话逐条改判成 FABRICATED / FAKE-GREEN 并删除代码。一个项目愿意把自己的卖点划掉，说明它的其它数字可信度相应提高。
3. **工程闸门全部真实存在且当前是绿的**：CI 配置（`lint-and-test`）跑了 format/lint/typecheck/test/playwright/build 六道；e2e 用例锚定 `data-testid` 而非 UI 文案；测试 698 个。
4. **测量口径写进了代码注释**：`runAnalytics.ts` 头部就写明「2 m 网格，单人读 0.25 P/m²」「一秒内往返会漏计」「行程只统计已离场的人」。知道自己量的是什么，是扎实的核心标志。
5. **代码体量健康**：最大文件 634 行，没有几千行的巨型文件。

**虚的地方（必须正视）**

1. **唯一副本**：`git remote -v` **为空**，同时工作区有 **60 项未提交改动**（46 改 + 13 新增 + `_to_delete/`、`.claude/`）。机器一坏，四天工作全没。这是当前**风险最高**的一条。
2. **CI 事实上从未跑过**：没有 remote，且本地分支是 `city-sim-engine`，而 CI 只在 `push: branches: [main]` 触发。所以「CI 绿」目前只是一个配置文件，不是事实。
3. **性能退化了并且被测试超时掩盖**：加入碰撞预判后，约 980 人每步 4.9 → **7.2 ms**；同时 5 个重型 spec 的超时被放宽到 20 s。放宽超时本身不是错，但它让「变慢」这件事从闸门里消失了。
4. **最大的性能卖点没接线**：见上文 B。
5. **有残留**：`bioCityWorkspacePackage.ts` 只被自己的测试引用（孤儿）；`_to_delete/` 里是上一轮留下的 `agentLifecycle.*`。
6. **e2e 在本机不可验证**：没有 Playwright 浏览器，这条闸门现在只能靠别人转述。

## 4. 接下来两周（P1）

1. **性能回补（最高价值）**：目标约 1000 人在 4× 倍速下仍实时。三个方向按性价比排：
   - 预判的邻居扫描改 SoA/TypedArray（现在可能是对象数组）；
   - 预判从 20 Hz 降到 10 Hz；
   - 只对「前方有人」的行人做预判。
     改完必须复测 `fundamentalDiagramHarness` 与迎面让行用例，并把 5 个超时调回去。
2. **给 100k GPU 核一个明确判决**：要么接回主链路（注意 ADR-0006 不得静默降级，需带标签的模式切换），要么在台账里写清「已实现、未接线、不在任何对外宣称里」。**不要让它继续处于「做了但没人知道算不算数」的状态**——这是目前最容易产生虚假宣称的地方。
3. **计数线编辑体验**：现在单击落一条固定 8 m 水平线，不能拖、不能改朝向、没有名字；而实测指标全靠它。
4. **疏散深化**：反应时间分布（当前全体瞬时反应）、出口选择模型、疏散专用报告字段。
5. **把 e2e 变成可复现**：本机装 Playwright Chromium，让这条闸门回到自己手里。

## 5. 结构性（P2，动工前先写 ADR）

- **多楼层 + 垂直交通**：先扩 schema（楼层、连接件、跨层寻路），再写 ADR。这是与 AnyLogic 等一线产品差距最大的一块，也是零售/车站场景绕不过去的。
- **真实轨迹标定**：需要公开轨迹数据集。**下载任何第三方数据集/模型资源之前必须先问你**——这是既定约定。
- **生产部署**：注入真实 login verifier（IdP 或账号表），否则部署后所有人都登录不了。

## 6. 现在**不要**做的事

- 不要再增加「AI」相关的表面功能。上一轮已经把没有模型参与的 AI 字样全部冻结，再往回走是自毁可信度。
- 不要为了让基准变绿而放宽期望区间。上一轮已经发生过一次（自证循环），台账里记着。
- 不要在性能回补之前再叠加新的行为复杂度——每加一个力，每步耗时就再涨一截，现在已经付过一次代价了。

## 7. 补记：CI 首次真正运行（同日晚）

仓库已建为私有仓库 `lige-garin/crowdsim`，分支 `city-sim-engine` 已推送，
`ci.yml` 的触发分支加入 `city-sim-engine`。**这是 CI 有史以来第一次执行。**

| 步骤                | 结果                                      |
| ------------------- | ----------------------------------------- |
| `pnpm format:check` | success                                   |
| `pnpm lint`         | success                                   |
| `pnpm typecheck`    | success                                   |
| `pnpm test`         | success（698 通过）                       |
| `pnpm e2e`          | **failure**：9 条中 8 条通过，第 8 条超时 |
| `pnpm build`        | skipped                                   |

**e2e 失败根因（已定位，未修）**：第 8 条
`build straight into the 3D city and undo it` 要点击 `viewport-canvas`，
而 ubuntu runner 没有 WebGPU，应用按 ADR-0006 显示了阻断卡
`data-testid="viewport-unsupported"`，它盖在 canvas 上拦截了点击，
`locator.click` 30 s 超时。

也就是说：**应用行为是对的**（无 GPU 就该 fail-loud，不静默降级），
是 e2e 没有适配无 GPU 环境。三个可选修法，需先定方向：

1. 给 CI 的 chromium 加 SwiftShader / `--enable-unsafe-webgpu`，让无头环境也有
   WebGPU —— 最正，但无头 Chromium 的 WebGPU 支持不稳定；
2. 该用例在检测到 `viewport-unsupported` 时 skip 并注明原因 —— 最省事，
   但 CI 从此不再覆盖「在 3D 城市里直接建造」这条路径；
3. 让阻断卡不拦截指针事件 —— 不推荐，那张卡本来就是要给人看的。

在修好之前，CI 每次推送都会是红的。
